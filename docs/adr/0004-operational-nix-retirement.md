# Finish operational Nix retirement on the existing hosts

- Status: Accepted; completion boundary amended 2026-09-11
- Decision owner: home-lab operator
- Accepted by: operator instruction to “proceed with this narrower boundary” on 2026-09-11
- Supersedes: only the completion boundary of [ADR 0003](0003-bounded-attended-migration.md)

Both hosts are already Ansible-owned and aggregate Proxmox cutover is complete. The owner now separates **Nix runtime retirement on those existing hosts** from **new lifecycle-controller adoption**. Finish by closing the bounded consumer trace for relevant installed boot, maintenance and backup paths: establish whether they require executing Nix, retain necessary non-Nix Python/data helpers and recovery assets, and remove only an actually identified obsolete dependency under separate exact approval. An empty removal list is acceptable; static reference counts or sampled absent paths are neither exhaustive live/external closure nor deletion authority. The [checklist](../host-lifecycle-completion-plan.md) records completion on 2026-09-11 for the reviewed existing-host paths, with the coverage exclusions below; this is not a universal filesystem or dependency certification.

This replaces this ADR's earlier requirement to qualify replacements, converge new source, execute a no-change run and certify same-revision no-op plans as retirement gates. The tradeoff is deliberate: existing-host runtime closure can finish while the new controller remains uninstalled/unqualified and a future clean rebuild remains **uncertified**. [ADR 0005](0005-attended-operational-admission.md)'s four-asset rollout, admission compatibility, native qualification, new-source convergence/no-change and source-aligned no-op-plan certification are deferred for this finish line, not passed or waived. Its guards still bind every future invocation of that controller. The journal-presence read was never approved or run and is now deferred; retaining recovery records requires no journal/lock disposition.

Keep current and previous Compose artifacts/images, protected storage/access, VM100 `scsi3`, boot `scsi3;net0` and absent `scsi0`, Restic/firewall recovery, inactive recovery media and records. Retained `nix/` Python/data is not itself Nix execution. Unknown operations and uncertain independent console/recovery custody still block relevant writes; they do not establish Nix use. No source rollback/deletion, host operation, package change, credential deletion, lock clearing, guard bypass or new read grant follows from this decision.

[ADR 0003](0003-bounded-attended-migration.md)'s per-operation approvals and failure/recovery rules, [ADR 0002](0002-advisory-maintenance-reporting.md)'s reporting deferral and [managed-OIDC ownership](../shared-oidc-ownership.md) remain. Rebuild, VM9901, fixture/toolchain, predecessor observer/Adapter and v6 work stay deferred. Preserve unshipped candidates and prior evidence/failures. The [short checklist](../host-lifecycle-completion-plan.md) separates source findings, installed observations and remaining unknowns without repeating ownership cutover or Docker qualification.
