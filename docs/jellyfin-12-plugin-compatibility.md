# Jellyfin 12.1 plugin compatibility

**Research cutoff:** 2026-09-20 (inclusive). **Scope:** the nine versions formerly installed on this host. Only Jellyfin-controlled sources and each plugin's first-party repository/catalog were used.

## Result

**Do not copy any of the old plugin binaries into Jellyfin 12.1.** Every installed artifact targets the 10.11 ABI, and Jellyfin's 12.0 release guidance says 10.11 plugins will not load on 12; plugins must be rebuilt for 12.0/.NET 10. The plugin version number itself is not the server compatibility indicator: catalog entries encode the build's server ABI in `targetAbi`. That field acts as a minimum-version catalog gate, not a maximum-version guarantee, so an old `10.11.*` entry can look eligible on a later server even though the major-version binary is incompatible. Jellyfin therefore instructs users to reinstall only explicitly rebuilt 12.x plugins after upgrading ([Jellyfin 12.0 release notes](https://jellyfin.org/posts/jellyfin-release-12.0/), [official release/version policy](https://jellyfin.org/docs/general/contributing/release-procedure/), [Jellyfin issue documenting the lower-bound behavior](https://github.com/jellyfin/jellyfin/issues/11331)).

Statuses below are evidence-based:

- **Confirmed incompatible** means the exact artifact is a 10.11 build, not a Jellyfin 12 rebuild.
- **Confirmed compatible** means the publisher has a separate artifact in its Jellyfin 12 catalog with `targetAbi` `12.0.0.0` or `12.1.0.0` (and, where stated, first-party documentation says 12+).
- **Unknown** is used where the primary evidence does not establish the claim. There are no guessed results.

## Key findings and severity

1. **Blocker — all nine exact binaries:** all target 10.11.x and are confirmed incompatible with Jellyfin 12.1. Reinstall by catalog version, never by copying the prior plugin directories.
2. **Blocker — EDL Creator:** there is no published 12.x version in its first-party 12 catalog.
3. **High — SSO:** a correctly targeted successor exists, but it is beta-only and expressly lacked manual live-server release QA at the cutoff; production reinstall is not presently “safe.”
4. **Caution — Merge Versions:** `12.0.1` fixes the Jellyfin 12.1 scan-splitting defect by using the server's native merge/split actions, but does not repair groups created by older plugin releases.
5. **Normal — the other seven:** first-party Jellyfin 12 builds exist; TMDb Box Sets `15.0.0.0` is the only examined release that explicitly raises its catalog target to the 12.1 ABI.

## Contradictions and evidence limits

- **Manifest eligibility is not proof of forward compatibility.** `targetAbi` is a lower bound and has no reliable upper-bound expression in these entries. That is why the separate 12 builds and publisher statements—not merely `12.1 >= 10.11`—control the result.
- The official catalog and community manifests are live/mutable URLs. The Merge Versions manifest assigns `12.0.1.0` an inconsistent future timestamp of 2026-10-17, while GitHub's immutable release record shows tag `12.0.1` was published on 2026-09-17. The release record and source comparison establish that it was available by this cutoff.
- No first-party runtime/E2E result was found for EDL Creator on 12 because no 12 artifact is published. No manual live-server release-QA result existed for Flowfin SSO 5.0.0.88; its own manifest says so.
- “Safe” here covers ABI evidence plus material first-party warnings found during review. It is not a substitute for backup, configuration migration review, or staging on this host.
