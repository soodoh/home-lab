# VM 100 ephemeral Nix inspection transport

Status: inspection tooling only. No production run is authorized by this document, and neither transport mode accepts an install request.

## Fixed export

The x86_64 Proxmox builder uses `scripts/controller/export-vm-100-ephemeral-inspection.py` from an exact clean pushed checkout. Its canonical mode-0600 request and independently supplied expectations bind:

- the full pushed commit and `nix/flake.lock` SHA-256;
- Compose artifact SHA-256 `aa550bfd004366bf85f58b661ed26d2a3ba3b72d5f01e4286b6d05117352f086`;
- `packages.x86_64-linux.vm-100-candidate-install` and its expected output path;
- the expected candidate toplevel;
- the `packages.x86_64-linux.vm-100-ephemeral-nix-bootstrap` output path;
- `x86_64-linux`, pinned Nix `2.34.8`, independently expected SHA-256 values for the exporter, runner, and shared `vm_100_ephemeral.py` helper, the closure public key, and one of the two exact transport modes;
- the exact SHA-256 of a distinct protected Proxmox host-attestation artifact for disposable VMID 9900.

`mode=qualification` requires `qualificationEvidenceSha256=null`. `mode=live-inspect` requires a non-placeholder prior qualification-evidence SHA-256. Both modes bind the same host-attestation SHA-256. A mode cannot be changed without changing both the canonical request and manifest. Before importing shared code, the tracked exporter launcher reads sibling `vm_100_ephemeral.py` exactly once, hashes that captured byte string using only Python standard-library code, and requires the separated `--expected-helper-sha256` argument to match. It compiles and executes that same captured byte string into a pre-registered `ModuleType`; normal import resolves the in-memory module and never reopens the helper pathname. The canonical request, manifest, export evidence, qualification evidence, and live qualification validation all bind those helper bytes. The exporter then validates the protected host-attestation bytes against an independently supplied hash, opens the fixed protected signing key through a stable no-follow descriptor and passes only `/proc/self/fd` to Nix. It builds only the fixed flake attributes with offline substitution disabled, asserts exact outputs, recursively queries every reference, SRI NAR hash, size and signature with pinned `nix path-info --json --sigs` semantics, and rejects any path not signed by the requested trusted key. It writes an uncompressed deterministic GNU bootstrap tar with hardlinks dereferenced, a complete `nix-store --export` stream, a canonical strict manifest, and export evidence into an empty root-owned mode-0700 directory. Every output is created mode 0600. Tar, signing, and export diagnostics are rejected rather than copied to output.

## Non-circular disposable qualification

Qualification does not claim prior qualification. The exact sequence is:

1. In a future separately approved Proxmox-host observation, the parent creates a root-owned canonical `home-lab-vm-100-ephemeral-host-attestation-v1` artifact. It binds VMID 9900, SeaBIOS, q35, the exact candidate serial/capacity, the observed SMBIOS product UUID, pushed commit, capture time, and a SHA-256 of the canonical PVE configuration observation. The parent transfers only this protected artifact and its independently reviewed byte hash through the approved protected channel. Repository tooling does not collect it and makes no PVE call.
2. Export the exact closure with a canonical `mode=qualification` request, null qualification hash, and the independent host-attestation hash.
3. Run the exact same `run-vm-100-ephemeral-inspection.py` inside disposable x86_64 VMID 9900. Supply both the distinct host attestation and a separate root-owned canonical qualification request containing VMID 9900, the disposable SMBIOS product UUID, the exact host-attestation hash, and literal confirmation `qualify-disposable-vmid-9900-inspection-only`. Independent exact hashes for the host attestation and UUID plus the same confirmation are supplied on the fixed runner command line. Host-attested VMID, protected request, independent hashes, and `/sys/class/dmi/id/product_uuid` must all agree; guest-derived request values alone are insufficient.
4. The qualification path performs the complete inspection-only bootstrap, signed import, closure/content verification, literal installer inspection, and cleanup. It emits qualification evidence only after both inspection and cleanup pass. The evidence records only the disposable product UUID hash and host-attestation byte hash, never the UUID value.
5. Hash that canonical qualification evidence. Export the same exact commit, bootstrap, installer, toplevel, signing key, bootstrap tar, and export stream with `mode=live-inspect` and that evidence hash.
6. Live VM100 mode independently requires the exact evidence hash, exporter hash, runner hash, trusted public key, commit, installer, toplevel, bootstrap hash, and export hash. It rejects qualification controls and any evidence from a different closure or tool byte sequence.

This breaks the prior circular dependency while keeping VM100 live use fail-closed. VMID 9900 identity comes from the independently hashed Proxmox host attestation and is cross-checked against the separate request and guest-observed SMBIOS UUID; the tooling does not contact PVE to discover or mutate it.

## Stable Arch-side consumption

The Arch runner requires independent expected hashes for the manifest, bootstrap, export, exporter, runner, shared helper, and exact source/store identities. Its standard-library launcher preflight reads and hashes the helper before importing it; a mismatch exits before helper code executes. On success it compiles/executes the exact already-hashed bytes into an in-memory module, so a pathname replacement after the read cannot change executed helper code. Because Python must execute the launcher itself, the reviewed delivery contract is the exact pushed exporter/runner/helper trio invoked directly from the clean checkout, with all three independently reviewed hashes. The request, manifest, qualification evidence, and live checks bind the helper hash. Live mode additionally requires the qualification evidence hash. The trusted public key is a mandatory independent command-line expectation and must equal both request and manifest; it is not accepted only through their protected chain.

All protected inputs are opened through descriptor-relative `O_NOFOLLOW` path traversal and must be root-owned mode-0600 single-link regular files. The bootstrap and export descriptors stay pinned. After mounting the bounded tmpfs, the runner copies the descriptor bytes into private tmpfs files while hashing, fsyncs them, makes them read-only, rehashes them, and executes only the copy descriptors. Tar extraction uses `/proc/self/fd` with an inherited descriptor; Nix import reads a duplicate of the consumed export descriptor. Replacing an original pathname after validation cannot alter consumed bytes. Canonical inspection and protected-disk requests are copied from already validated bytes into the same tmpfs and only those copies are passed to the installer guard.

The runner rejects non-x86_64 execution, installation/Nix environment injection, any persistent `/etc` or root Nix config/profile/plugin path, any preexisting `/nix`, a Nix daemon/socket, low memory/inodes, unsafe tar members, a nonempty output directory, and any identity mismatch. It checks memory before mounting and checks inode capacity on the bounded tmpfs itself, rather than trusting persistent-root inode counters that are always zero on filesystems such as Btrfs. It creates empty HOME, XDG config/cache, temporary, and user-config paths on the tmpfs. Every Nix invocation receives fixed `NIX_CONFIG`, `NIX_USER_CONF_FILES`, `NIX_PATH`, local-store, empty plugin/builder/substituter settings, no flake feature, no `NIX_PATH`, and the one independently expected trusted key. The recursive bootstrap closure may contain both the `pkgs.nix` lndir aggregate and underlying executable-bearing requisites. The runner never scans that closure for a unique executable. It derives `bin/nix` and `bin/nix-store` only from the exact runner-CLI expectation `bootstrapStorePath`, which must equal the explicit request and manifest fields, requires both to be executable after extraction, and still requires the complete recursive bootstrap closure. It authenticates the signed export during supported pinned `nix-store --import` with `require-sigs=true` and the sole independently expected `trusted-public-keys` value. Legacy import verifies but does not persist stream signatures in the destination database, so post-import verification does not incorrectly require them there; instead it proves exact import output, closure-set equality, physical store-path equality, SRI NAR hashes, references, sizes, signature-field shape, and every imported NAR's contents with pinned `nix path-info --json --sigs` and quiet `nix store verify --no-trust`. It then rechecks stable boot and candidate disk identities and invokes the literal imported installer through a network namespace with only a canonical `mode=inspect` request. It never evaluates, builds, substitutes, uses channels/registries, contacts a network, or invokes Docker, PVE, SSH, Disko, or `nixos-install`.

A mount return code of zero marks `/nix` as mounted before diagnostics are evaluated, so even a successful mount that emitted forbidden diagnostics is still unmounted during failure cleanup. For anomalous nonzero mount results, `findmnt` is consulted; an observed mount or ambiguous mount observation conservatively marks it mounted and triggers unmount cleanup. Cleanup always attempts a normal unmount, never lazy or forced unmount. Evidence passes only when the complete installer process group is absent, `findmnt` independently proves no `/nix` mount, `/nix` is absent, the boot ID remained stable, and all tmpfs transport paths are gone. The output directory is opened once through no-follow directory descriptors and must be empty before work. That one descriptor remains pinned across metadata/emptiness checks, exclusive evidence writes, file and directory fsyncs, and final entry checks. Before and after publication, a fresh no-follow pathname traversal must resolve to the pinned device/inode. Inspection evidence is written first, cleanup evidence second, and qualification evidence last; qualification is withheld unless both prior evidence writes and both underlying proofs succeed. A partial output can never contain an authorizing qualification artifact.

## Disk inspection contract

The runner resolves each by-id once, proves both targets are block devices, and runs `lsblk`, `wipefs`, holder, and opener observations only against the exact resolved candidate. It proves both by-id mappings unchanged before and after observation. Immediately before invocation, both the runner and imported installer guard require the fixed candidate by-id, exact serial `QUAL-NIXOS-128G`, and exactly 137438953472 bytes. They reject partitions/children, filesystem or partition signatures, mounts, holders, openers, opener diagnostics, or identity changes. The resolved candidate must differ from all mounted block sources and the authoritative protected games-disk input. The games by-id is compared in memory and is never written into evidence or logs. The runner supplies a canonical tmpfs handoff binding the exact resolved candidate, boot ID hash, serial, size, and inspect mode. The installer guard reads all three protected leaf files through stable no-follow descriptors, requires its repeated resolved-device observations to equal that handoff, and the runner repeats the full disk observation after the child exits. The guard requires exact request/handoff mode equality and accepts only `handoff.mode=inspect`; therefore an install request fails before the installer wrapper can reach Disko or `nixos-install`, even if the legacy confirmation environment is supplied. Future destructive work requires a separate generation and authorization and remains blocked.

## Residual qualification gate

No disposable qualification or live runner invocation is performed by repository validation. A real disposable VMID 9900 run must still create reviewed qualification evidence. This evidence attests only exact bootstrap/import/inspection mechanics. A later destructive installation requires separate disposable SeaBIOS install-and-boot qualification and explicit production approval; this tooling contains no such invocation.

The x86_64 flake check `vm-100-ephemeral-nix-cli` binds Nix 2.34.8, requires literal `nix` and `nix-store`, proves supported path-info/store-verify/import options including content-only `--no-trust` verification after authenticated legacy import, and rejects the unsupported legacy signature flags.

Strict schemas are under `infrastructure/vm-100/ephemeral-*.schema.json`. Hostile fixtures are integrated into `scripts/reconcile-infrastructure validate` through `test-vm-100-ephemeral-inspection.py`.
